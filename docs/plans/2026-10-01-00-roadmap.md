# Implementation Roadmap — module by module

**Date:** 2026-10-01 · **Revised:** 2026-10-03 (stack chosen by the owner; frontend follows the portal prototype) · **[v3] Revised:** 2026-10-07 (module order realigned to Engineering Spec v3's six phases and gates)
**Source documents:** [../BRD.md](../BRD.md), [../architecture.md](../architecture.md), [../design.md](../design.md), [../specs/](../specs/) (especially [CHANGELOG-v3](../specs/CHANGELOG-v3.md) §11 and §14), [../feature-list.md](../feature-list.md), [../design-reference/complyiv-portal-audit.html](../design-reference/complyiv-portal-audit.html)

The system is built one module at a time. Each module gets its own
bite-sized plan in this folder when its turn comes, so every plan is
executable without reading the others. **Module 1 is the frontend**, built
against a mock API that encodes the real contract; every later module
replaces one part of the mock with a real implementation and must keep the
frontend's tests passing.

Still proposed, confirmed in the plan of the module that first needs each: pytest for backend tests, and a local KMS stand-in for per-client keys. **[v3]** v1.1's S3 Object Lock evidence store is dropped: CiV keeps fingerprints, not content (owner decision 2026-10-07, D18). A legal-hold snapshot goes to a bucket **the client owns**, so MinIO is needed only to test that path. Details and status of each row: [../architecture.md](../architecture.md) §6.

The portal only calls paths under `/api`. In module 1 a mock inside the Next.js app answers them; from module 3 (the portal API) Next.js forwards `/api/*` to the Django API.

## Rules every module plan follows

- **The frontend contract is fixed by module 1.** `frontend/src/api/types.ts` is the contract. A backend module that needs a contract change updates the types, the fixtures, the affected frontend tests and design §14 in the same plan. **[v3]** Step 1b updates the contract for v3 first. From module 3 an automated check compares Django's OpenAPI schema with the contract file.
- **The portal file is the design source of truth** (`complyiv-portal-audit.html`). Where it and the specs differ, the specs win. **[v3]** That now means v3: source grades A–D, S, N (not tiers; wording per D30), worst-case values, "DNC check records"; still M08 6.0 h and "possible (location uncertain)".
- **[v3] No client content at rest.** No module writes a client record, message text, recording, certificate content or raw phone number to disk; every module's tests include that check.
- **Parameters come from the rulebook**, never hard-coded (module 3 onward).
- **The wording guard** runs in every test suite that renders or generates client-visible text: `frontend/src/lib/wording.ts` in the portal, and a Python twin with the same list in the backend from module 13. **[v3]** The list adds four list-cleaning words and "court-ready" (see README).
- **"Not measured" is a first-class value** in every type; no module may turn it into 0. **[v3]** In scoring, an unverified input takes its worst-case value and is flagged `worst_case`; the display still names the missing source.
- **Separate folders, separate files.** `frontend/` and `backend/` never import from each other. Each module has its own files: one Django app per backend module; one React component per file in the frontend — never a single file holding several components. A module's plan lists every file it creates and touches no other module's files except through a defined interface.
- **Short comments where needed.** One line, only where the reason is not obvious from the code.
- **Local first.** Every module must run and pass its tests on a developer machine with local PostgreSQL and Redis; nothing may depend on a hosted service until hosting is chosen.
- **No git steps in plans** until version control is set up; each plan ends with a verification task instead.
- **Phase gates** from the spec (§11) apply **[v3]** as listed in the module table: module 8 is not done until 200 hand-checked contacts agree (Gate 2); modules 12–13 are not client-visible until counsel items for Gate 4 are set; module 17 is not shown to a buyer until Gate 5.
